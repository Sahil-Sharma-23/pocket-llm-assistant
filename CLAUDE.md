# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What this is

A local-first personal AI assistant that runs **inside Termux on an Android
phone**: one Go process (`cmd/assistant`) plus a supervised `llama-server`
child running Gemma 4 E2B. Interfaces: a Telegram bot (long polling) and a
loopback-only web dashboard on `127.0.0.1:8787`. See `README.md` for usage and
`docs/ARCHITECTURE.md` for the component map.

**Setting up a phone?** Use the `/setup-phone` command
(`.claude/commands/setup-phone.md`). It drives a USB-connected phone through
`scripts/adb-termux.sh`.

## Commands

```sh
make check           # gofmt check + go vet + tests: run before every commit
make test            # go test -count=1 -cover ./...
make test-race       # workstation only (no race detector on android/arm64)
make build           # CGO_ENABLED=0 build into bin/assistant
go test ./internal/agent -run TestName -v      # single test
./bin/assistant -config configs/config.example.json -check-config   # validate config
```

On the phone (Termux), build with `GOFLAGS=-p=2 make test build` to bound
compile memory. From a computer: `scripts/adb-termux.sh push` then
`scripts/adb-termux.sh run 'cd personal-assistant && GOFLAGS=-p=2 make test build'`.

## Invariants (do not break these)

- **No cloud LLM.** `internal/llm` may only dial loopback (`llm.loopbackOnly`,
  enforced after DNS resolution). Do not add a remote fallback provider.
- **Loopback-only servers.** `server.addr`, `llm.base_url` and llama-server's
  host must be loopback; config validation rejects anything else. The API
  checks the Host header against DNS rebinding.
- **Permissions live in Go, never in model output.** A tool's level
  (`tools.Spec.Permission`: Read / Write / Sensitive) is fixed in code. The
  executor looks it up by name. Arguments are strictly decoded (unknown fields
  rejected). Sensitive tools always go through an approval, whose summary is
  generated by Go (`Summarize`), not by the model.
- **Model-proposed URLs use the public-only dialer** (`research.publicOnly`):
  no loopback, private, link-local or CGNAT targets, re-checked on redirects.
- **Secrets only via environment.** Config files hold env-var *names*
  (`token_env`); tokens live in `configs/secrets.env` (mode 600, git-ignored).
  Never log message text, prompts or tokens.
- **Pure Go, CGO-free** (`modernc.org/sqlite`). The binary must build natively
  in Termux.
- **Crash-safe by design.** Android can SIGKILL anything at any time. Use
  SQLite transactions and atomic state transitions; approvals are
  at-most-once and never re-executed after a crash.

## Android / Termux gotchas

- **Build release binaries in Termux.** Upstream-Go cross-compiled binaries
  cannot resolve DNS on Android (no `/etc/resolv.conf`). The Makefile forces
  `GOTOOLCHAIN=local` inside Termux for the same reason.
- **Time zone.** Go on Android ignores `TZ` and uses UTC. `internal/config`
  resolves `$TZ` (exported by `scripts/env.sh` from `getprop persist.sys.timezone`)
  or the `timezone` config key, and `cmd/assistant` sets `time.Local` explicitly.
- **Restricted `/proc`.** SELinux blocks `/proc/stat`, `/proc/loadavg`,
  thermal and battery sysfs; `internal/sysinfo` uses only `/proc/meminfo` and
  `/proc/<pid>/status`.
- **Termux:Boot** runs hooks without `termux-exec`, so `#!/usr/bin/env` fails
  there. The boot hook calls everything via `$PREFIX/bin/bash`. Keep scripts
  invoked as `bash scripts/x.sh`, not via their shebang.
- **Slow inference.** It runs at about 8 tok/s prompt and 4–5 tok/s
  generation on mid-range phones. Keep prompts short and static-first (prompt
  cache), clip tool output, prefer deterministic `/commands` and Go-rendered
  confirmations (`Spec.Confirm`) over extra LLM calls.
- **Memory.** Weights are mmap'd (reclaimable). The guard enforces
  `llm.min_free_mem_mb`; the supervisor refuses to start llama-server below
  `min_free_mem_mb_to_start`.

## Where things go

- **New tool:** add a `tools.Spec[In, Out]` in `internal/tools/` with a JSON
  schema, permission, timeout, and `Summarize`/`Confirm` where relevant;
  register it in `tools.All` (`internal/tools/deps.go`); allowlist it for the
  right agent in `agent.DefaultAgents` (`internal/agent/registry.go`). Add
  tests for validation and permission behaviour.
- **New agent:** add it to `DefaultAgents`, with routing keywords/description
  and a minimal tool allowlist.
- **Schema change:** add a new `migrations/NNNN_description.sql` file. Never
  edit an applied migration.
- **New config key:** add it to `internal/config` (default plus validation),
  `configs/config.example.json`, and the README table. Unknown keys are
  rejected, so all three must agree.
- **Phone setup / operations:** `scripts/termux-setup.sh` (in Termux),
  `scripts/adb-termux.sh` (on the computer), `docs/ANDROID.md`, and the
  `/setup-phone` command. Keep these four consistent.

## Conventions

- Table-driven tests with fakes (`agent_test.go` has a fake LLM; the
  Telegram and HTTP tests use `httptest`). Tests must not touch the network
  or need a model.
- Errors are wrapped with context (`fmt.Errorf("…: %w", err)`); logging is
  structured `slog`.
- Keep docs device-agnostic. Benchmarks are labelled as coming from a
  *reference phone*. Do not commit personal data, device serials, Telegram
  IDs or tokens.
